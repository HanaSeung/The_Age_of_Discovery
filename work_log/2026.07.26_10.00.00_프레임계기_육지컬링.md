## 10. WebGL 결정 — 업계 방식 문답 두 번

> H: 이 경우 통상적으로 업계에서는 어떻게 해결하는가?

컬링 후 리스본·지중해 20fps / 먼바다 100fps 실측을 놓고 업계 답 넷을 정리:
A 뷰포트 클리핑, B 벡터 타일, C 렌더 캐시(미니맵이 이미 사용), D GPU(WebGL).
추천을 (선분 stroke 안에서) C 로 바꿨다.

> H: 업계의 통상적인 방식과 비교했을 때 최고의 방식은 무엇인가?

절대 성능의 최고 = D (모든 현대 지도·게임 엔진의 종착지), 이 프로젝트의 최고 = C
(검증 기반·단일 파일 원칙과의 비용 저울)로 갈라 답함.

> H: D WebGL로 하자.

D 확정. 어중간하면 최악이므로 설계 넷을 먼저 승인받음: ① 삼각분할은 부팅 때
earcut(빌드 때는 자료 5배 증가로 기각) ② stroke 는 1단계에서 2D+CSR 선분 색인
③ GL 실패 시 landCull 후퇴 유지 ④ Node 에 GL 없음 — 삼각분할·수집은 수치 검증,
화소는 브라우저 실측이 최종 판정.

## 11. WebGL 1단계 구현 — 혼성 3층

**earcut 2.2.4** 공식 배포본(unpkg, 7,131B, ISC) + LICENSE 동봉, `SOURCES_LICENSE.md` 기록.

**3층 구조** (업계 표준 혼성 — GL 기반지도 + 2D 오버레이):
- `#cb` 아래 2D: VOID 배경·바다·수심(BATHY)·항정선·경위선
- `#cg` 가운데 WebGL: 육지 채움 (투명 clear + 삼각형)
- `#c` 위 2D: 해안선 stroke·경계·해류·바람·배·덮개·계기 (투명 배경, 매 프레임 clearRect)

loop 이 불투명 VOID 를 칠하고 있어 단순 2층이 불가능했던 것이 3층의 이유.

**구현 내역**:
- 디코더에 고리 좌표 원본 `c:Float32Array` 보존 (3.3MB) — 삼각분할 원료
- `GLL` 모듈: 감김 방향(부호 면적)으로 구멍 검출 → 점-폴리곤 검사로 바깥 고리에 배정
  → earcut → 정적 GPU 버퍼 (색인 없는 삼각형 나열, OES 확장 회피). 검증 결과
  **404,190 삼각형, 구멍 1(카스피해)**
- 셰이더: 카메라 상대 좌표 (`aP + uOff - uCam` 을 셰이더에서 먼저 빼 float32 로
  배율 100 정밀도 확보 — 업계 표준 수법)
- `coastStrokePath(k)`: 충돌 CSR 색인에서 화면 안 선분만 수집, 이웃 번호+끝점 공유면
  lineTo 로 이어 폴리라인 (반투명 음영의 이음 덧칠 방지). `SEG_STROKE_MAX=150000`
  초과 시 null → 통짜 후퇴 (저배율)
