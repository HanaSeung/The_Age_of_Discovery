## 2. 극 너머가 해도에 보인다 — 진단

> (이미지 둘 첨부) 남과 북 끝까지 가면 미니맵에 지도를 벗어난 영역이 표시된다.
> 이것을 해결하길 원한다. 이해한 것을 설명만 하라.

원본을 읽어 **버그가 아니라 설계 결정이 드러난 것**임을 확인했다. `doBake()` 의 첫 두 줄이다.

```js
bctx.fillStyle = VOID; bctx.fillRect(0,0,pw,ph);          // 해도 밖 (극 너머)
const yT = Math.max(0, by), yB = Math.min(WORLD_H, by+bh);
if(yB > yT){ bctx.fillStyle = DIAL_SEA;
             bctx.fillRect(0, (yT-by)*k, pw, (yB-yT)*k); }
```

조각 전체를 `VOID`(`#20302d`)로 깔고 **월드 안쪽 띠(`0…WORLD_H`)에만** 바다를 덮는다.
배가 극 가까이 가면 조각이 `y<0` 또는 `y>WORLD_H` 를 물어 그 몫이 `VOID` 로 남는다.

본 화면도 같은 처리이며(`bctx.fillStyle=VOID` 로 아래층 바탕), 주석에 이미
**"해도 밖 = 미지의 바다"** 라고 적혀 있다. 다만 기준 배율 100 에서 본 화면이 담는 것은
94km 뿐이라 **본 화면에는 영영 안 보인다.** 해도만 그것을 드러낸다.

### 왜 하필 그 두 사진인가

배는 극에 닿지 못한다. `Y_TOP`·`Y_BOT` 이 변위를 미리 잘라 낸다.

```js
const Y_TOP = (90-84)*DEG2PXY, Y_BOT = (90-(-80))*DEG2PXY;   // +84° ~ -80°
```

사진 둘의 `84.0°N`·`80.0°S` 는 **정확히 이 한계값**이었다. 극까지 남은 거리가 북 6°·남 10°
로 고정되어 있으므로, 해도 반지름이 그보다 크면 반드시 `VOID` 가 들어온다.

| 단 | 지름 | 반지름(위도) | 북(6° 남음) | 남(10° 남음) |
|---|---|---|---|---|
| 1~3 | 250~1000km | 1.12~4.49° | — | — |
| 4 | 2000km | 8.98° | **보인다** | — |
| 5 | 4000km | 17.97° | **보인다** | **보인다** |
| 6 | 8000km | 35.94° | **보인다** | **보인다** |

경계 위치를 재 보면 사진 둘 다 **5단(4000km)** 이다. 6단에서는 북쪽 기준
반지름의 83%가 `VOID` 가 된다.

세 갈래를 냈다 — **안 1** 세상의 끝으로 못박기(띠 색 + 90° 획), **안 2** 극을 접어 잇기
(지리적으로 옳으나 갈 수 없는 바다를 그린다), **안 3** 해도를 지도 안으로 끌어당기기
(`VOID` 는 사라지나 **배가 원의 한가운데를 떠난다**). 안 1 을 추천했다.

## 5. 설계 — 지형이 아니라 규칙이다

본 화면에 그린다는 결정에서 구조적 이점 셋이 따라 나왔다.

**1. 경도 순환과 무관하다.** 본 화면은 `k=-1…1` 세 벌을 겹쳐 그리는데(이음매 처리),
가로선은 모든 경도에 걸쳐 있으므로 그 되풀이에 낄 필요가 없다. 화면 폭을 가로지르는
한 줄이면 끝이다.

**2. 화면좌표로 그린다.** 월드 변환 안에서 그리면 배율이 굵기와 점선 간격을 함께 늘린다
(지금 코드가 `lineWidth = 1/zoom` 으로 나누는 이유다). 기준 배율 100 에서는 점선 간격까지
`/100` 로 적어야 하고 배율이 바뀌면 리듬이 흐트러진다.

```
화면 y = H/2 + (Y_TOP - ship.y) * zoom
```

**이것이 옳은 이유는 취향이 아니다** — 이 선은 지형이 아니라 규칙이다. 지형은 확대하면
커져야 하고, 규칙은 커지면 안 된다.

**3. 필요할 때만 나타난다.** 배가 실제로 멈추면 배는 정확히 `Y_TOP` 에 서고 화면
한가운데에 있으므로, 선은 배의 정중앙을 지난다. 결정하신 "배 밑으로 통과"가 그 그림이다.

남은 물음 셋(굵기·점선 리듬 / 밤에 함께 어두워지는가 / 두 줄을 같이 다룰 것인가)을 냈다.

## 6. 구현

`drawRhumb` 다음에 상수 다섯과 함수 하나를 넣고, 그리기 고리에서 `drawShip()` 바로
앞에 불렀다. 고른 값은 굵기 2.6px · 점 9px · 틈 7px, 밤에 함께 어두워지는 쪽이다.

```js
const LIM_C    = '#000';         // ★ 순검정 — 지형의 어느 획보다 세다. 규칙이므로 그렇다
const LIM_W    = 2.6;            // ★ 굵기(화면px) — 배율과 무관하게 일정하다
const LIM_DASH = 9;              // ★ 점 하나의 길이(화면px)
const LIM_GAP  = 7;              // ★ 점 사이 틈(화면px)
const LIM_Y    = [Y_TOP, Y_BOT]; // 북·남 두 줄 — 값만 다른 같은 것이라 표 하나가 돈다
function drawPolarLimits(){
  screenTransform();
  ctx.save();
  ctx.strokeStyle = LIM_C; ctx.lineWidth = LIM_W;
  ctx.setLineDash([LIM_DASH, LIM_GAP]);
  ctx.beginPath();
  for(const wy of LIM_Y){
    const y = H/2 + (wy - ship.y)*zoom;
    if(y < -LIM_W || y > H + LIM_W) continue;   // 화면 밖이면 그릴 것이 없다
    ctx.moveTo(0, y); ctx.lineTo(W, y);
  }
  ctx.stroke();
  ctx.restore();                                // 점선 설정이 뒤로 새지 않게
}
```

`/zoom` 나눗셈이 한 번도 나오지 않는다. 배율은 **자리를 정할 때만** 쓰인다.
`save/restore` 로 감싼 것은 `setLineDash` 가 뒤따르는 획으로 새지 않게 하기 위함이다.

호출 자리는 `drawWindArrows()` 와 `drawShip()` 사이다. 배가 위에 오고, 구름·비·밤이
이 선을 함께 덮는다 — 지형과 같은 대접이다.

### 묵은 파수꾼이 걸렸다 — 이 세션에서 가장 값진 것

전체를 돌리자 엉뚱한 파일이 하나 죽었다.

`verify_minimap.js` §11 은 **원본에서 상수 무리를 통째로 긁어 자기 샌드박스에 넣는
검증들의 목록**을 지키고 있었다. 미니맵 시절 `SEA_C` 를 지었다가 `verify_precip`·

**파수꾼이 정확히 제 몫을 한 것**이다 — 새 의존이 생겼다고 알려 온 것이다.

고치는 길이 둘이었다.

1. 목록에 `verify_ship.js` 를 더한다 — 한 줄
2. 목록에 더하고, **감시 접두어에도 `LIM_` 을 넣는다**


기준 배율 100 에서 화면 세로 폭 ≈ 25km

## 부록 C. 이번에 효과가 있었던 방법

**1. 진단이 요청을 바꾼 것.**
"미니맵의 `VOID` 를 고쳐 달라"로 시작했으나, 읽어 보니 그것은 의도된 것이었고
정작 없는 것은 **"배가 왜 멈추는가"에 대한 표시**였다. 요청을 그대로 받아
`VOID` 부터 손댔으면 진짜 빈자리는 그대로 남았을 것이다.

**2. 두 경계를 분리해 말한 것.**
84°/90° 는 뜻이 전혀 다른 선인데 화면에서는 가까이 붙어 있다. 이것을 섞어 두면
"어두운 띠"와 "검은 선" 둘 다 무엇인지 물어보게 된다. 표 한 줄로 갈라 놓은 것이
결정 3(본 화면에 그린다)을 이끌어 냈다.

**3. 미리보기가 말을 이겼다.**
안 2(극 접기)는 말로는 "지리적으로 옳다"였다. 그려 놓으니 갈 수 없는 땅이 거울처럼
붙은 그림이 되어 왜 안 되는지가 한눈에 보였다. 직전 세션들의 교훈과 같은 계열이다.

**4. 지형과 규칙을 가른 것.**
"지형은 확대하면 커져야 하고, 규칙은 커지면 안 된다." 이 한 줄에서 화면좌표로
그린다는 결정, `/zoom` 을 쓰지 않는다는 검사, 순검정이라는 색이 전부 따라 나왔다.
값을 고르는 대신 기준을 세우면 그 뒤가 저절로 정해진다 — `clampStep()`·`RING_R` 과 같다.

**5. 파수꾼을 반쪽으로 고치지 않은 것.**
`verify_minimap` §11 이 걸렸을 때 목록에 한 줄 더하면 초록불이 켜졌다. 그런데 그 파수꾼은
목록과 접두어 **두 축**으로 서 있었고, 목록만 고치면 계기가 나중에 `LIM_*` 를 지어도
아무도 모르는 상태가 된다. **초록불을 켜는 것과 지키는 것은 다르다.**

**6. 검사가 형태 대신 결과를 본 것.**
`drawPolarLimits` 를 오려 내어 가짜 `ctx` 에 실제로 그리게 했다. 정규식만으로는
"함수가 있다"까지만 알 수 있고 "선이 배를 지난다"는 알 수 없다. 정보 카드가
`position` 하나 없이 모든 검사를 통과했던 일(직전 세션)의 대책이 이것이다.
