## 4. 되돌린 것 (1) — "해류를 모른다" 는 틀린 말이었다

> 왜 해류를 모른다고 하는가? 해류가 구현되어 있지 않은가?

지적이 맞았다. 주석에 "해류를 모르므로 같은 위도면 온도가 같다" 고 썼는데,
해류는 `currents_data.js` 42.5KB, NASA OSCAR 로 **이미 구현되어 있다**.

정확히 말해야 할 것은 이것이었다: **있는 것은 해류의 속도(u/v)이지 수온이
아니다.** 만류가 노르웨이해를 데우는 건 따뜻한 물이 실려 가기 때문인데,
그 계산을 하려면 온도장을 유속을 따라 이류시켜야 한다. 속도를 안다고 온도가
저절로 나오지 않는다. 주석을 정정했다. **커밋 `01dde63`**

### 확인 중 추가로 발견한 것 — 해류에 계절이 없다

> 지금 해류는 계절별로 변하지 않는다는 거지?

맞다. 확정적인 증거는 **함수 서명**이다.

```
339  function sample(wx, wy, out)            ← 해류: 달을 안 받는다
378  function sample(wx, wy, monthF, out)    ← 바람
422  function sample(wx, wy, monthF)         ← 구름
```

| | 출처 | 격자 | 시간축 |
|---|---|---|---|
| 바람 | NCEP/NCAR 월별 기후값 | 90×45 | 12개월 |
| 구름 | NCEP/NCAR 월별 기후값 | 90×45 | 12개월 |
| **해류** | NASA OSCAR **2014-01-31** | 180×90 | **없음 (하루)** |

격자는 해류가 더 촘촘한데 시간축이 통째로 없다.

**이게 이 게임에서 특히 걸리는 이유**: 대부분의 해류는 계절 변화가 작지만
**인도양은 몬순 때문에 방향이 뒤집힌다.** 소말리 해류는 여름 남서몬순에
북동으로, 겨울 북동몬순에 남서로 흐른다. 하필 박혀 있는 것이 **1월 31일 —
겨울 북동몬순 상태**다. 게임 속 인도양은 사철 겨울 해류로 고정되어 있다.

바람은 월별이라 몬순 풍향 반전이 이미 들어와 있다. **바람만 뒤집히고 해류는
안 뒤집히는 어긋난 상태**다. 1500년 배경에서 아랍·인도 교역망 전체가 몬순의
계절 반전 위에 세워져 있었으므로 사소한 문제가 아니다.

→ **별도 항목으로 세워둠. 이번 세션에서는 다루지 않았다.**

## 7. 되돌린 것 (3) — 수온 근사로는 비/눈을 못 가른다

강수 자료를 바꾸고 검증하니 45건 중 **1건이 남았다**.
`남극해 겨울(65°S, 7월)` 이 눈이 아니라 비로 나온다.

문턱을 올려 넘길 수 있는지 확인했다.

```
문턱 1℃ : 네 경우 모두 통과 ✓
문턱 2℃ : 그린란드해 여름이 눈이 되어 깨짐 ✗
```

**1℃면 통과한다. 그런데 그건 우연이다.** 기온 함수의 실제 오차는 이랬다.

| | 모형 | 실제 | 오차 |
|---|---:|---:|---:|
| 60°N 1월 | 0.41 | ~6 | **−5.6** |
| 72°N 7월 | 1.14 | ~5 | **−3.9** |
| 55°S 1월 | 7.36 | ~3 | **+4.4** |
| 65°S 7월 | 0.42 | ~−1.5 | **+1.9** |

고위도에서 3~6℃씩, 그것도 **부호가 양쪽으로** 어긋난다. 이런 오차 위에 얹은
문턱은 시험한 네 지점만 맞고 시험하지 않은 곳에서는 틀린다.
**통과하도록 문턱을 맞추는 건 검사를 속이는 것이지 고치는 게 아니다.**

> 지금 받아오자.

### `build_airtemp.py` — 실측 2m 기온

핵심 근거: **비가 눈이 되는지를 정하는 것은 물 온도가 아니라 공기 온도다.**
수온은 그 대용품이었고, 대용품의 오차와 근사의 오차가 겹쳐 있었다.

```
출처   NCEP/NCAR Reanalysis 1, air.2m.mon.ltm.nc
단위   K − 273.15 = ℃ (평균값 보고 켈빈 여부 자동 판별)
양자화 baseC −75℃ 에서 0.5℃ 단위 uint8
       (처음 −60 으로 잡았다가 남극 내륙 −70.8℃ 에서 361칸 잘려 −75 로 낮춤)
결과   airtemp_data.js 64KB
```

## 8. 3단계 — 그리기 `precipVeil`

> 3단계를 계속하라.

화면에 붙은 방울 900개를 실시간으로 떨어뜨리고, 각 방울이 덮은 월드 좌표로
`precipAt` 을 물어 비·눈·없음을 정한다.

### 설계 요점 셋

1. **자리를 붙박고 시간만 흘린다.** 매 프레임 난수를 뽑으면 방울이 제자리에서
   깜빡이지 떨어지지 않는다. 위치는 고정 `Float32Array` 에 담고 `precipT` 만 올린다.
2. **세기는 방울 수로 표현한다.** 방울마다 고정된 문턱이 있어 강수 세기가 그
   문턱을 넘는 것만 그려진다.
3. **낙하 시계는 실제 시각을 따른다.** 게임 배속을 48시간으로 올렸다고 비가
   24배 빨리 떨어지면 화면이 깨진다. `update()` 에서 `precipT += dt` (TIMEK 없이).

그리는 순서는 **구름 다음, 밤 앞**. 비는 구름 속에서 내리므로 구름보다 뒤에
오고, 밤은 지도·구름·비를 한꺼번에 덮어야 하므로 셋 다 뒤에 온다.

패널에 `비눈 표현`(0~1), `비눈 세기`(0~2) 추가.

### 짚어둔 설계 선택

위에서 내려다보는 해도에 떨어지는 비를 그리는 것은 **엄밀히는 앞뒤가 맞지
않는다.** 하늘을 위에서 보면 빗줄기는 점으로 보일 것이다. 등불(밤 표현 2번)과
같은 이유로 사실성보다 가독성을 골랐고, 주석에 명시했다. 지도에 얹어 바람 따라
흐르게 하는 방식도 가능하므로 필요하면 표현 번호를 늘려 나란히 둔다.

### 커밋 `1bbed57` — 시야 통합(updateSight)

```

f = (1 − 밤어둠×visNight) × (1 − 구름×visCloud) × (1 − 비눈세기×visRain)
```

## 부록 C. 유효했던 작업 방식

1. **검증 스크립트를 실측과 맞댄다.** "게임이 그렇게 계산했으니 맞다" 가 아니라
   `vm` 으로 함수만 떼어내 관측 기후값과 대조. 이 방식이 아니었으면 운량 유도의
   오류는 그대로 지나갔을 것이다 — 페루가 흐리다는 건 자료상 사실이고, 거기서
   비가 안 온다는 건 **자료 밖의 지식**이었다.
2. **검사가 실패하면 코드부터 의심하지 않는다.** 이 세션에서 실패 8건 중
   **6건이 검사 쪽 문제**였다(격자 상수 파싱, 어는점 걸림쇠, 측정 배율,
   낙하 측정법, 그리고 기존 검사 2건).
3. **문턱을 맞춰 통과시키지 않는다.** 남극해 1건은 문턱 1℃면 넘어갔지만
   그건 우연이었다. 오차 구조를 확인하고 자료를 바꾸는 쪽을 골랐다.
4. **`git worktree` 로 HEAD 와 대조**해 기존 실패와 내가 만든 실패를 가른다.
5. **파이프라인을 베낀다.** `build_cloud.py` → `build_precip.py` →
   `build_airtemp.py` 로 갈수록 빨라졌다. 격자·달 수를 맞춰 두면 칸이 겹친다.
6. 원본 캐시는 `.gitignore` 로 빼되 **`.dds` 로 격자를 먼저 확인**해서,
   창구가 바뀌면 엉뚱한 값을 만드는 대신 거기서 걸리게 한다.
