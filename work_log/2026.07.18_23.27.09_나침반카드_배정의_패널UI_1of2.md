## 18. 패널을 카드형으로

> 두번째이다.. 흐림은 할 필요 없다.

`#tune` 을 화면 끝에 붙은 판에서 **떠 있는 카드**로 바꿨다.

```css
#tune{position:fixed;top:14px;right:16px;width:290px;
  max-height:calc(100vh - 150px);
  border:1px solid rgba(122,90,52,.55);border-radius:6px;}
```

`bottom` 을 없애 높이가 내용을 따라가게 하고, 나침반 자리를 침범하지 않도록 최대 높이만 걸었다.
검증도 `bottom` 대신 `top` + `max-height` 로 바닥을 계산하도록 고쳤다.

## 19. 스크롤바가 메뉴를 밀어낸다

> 스크롤바가 생기면 패널의 메뉴들이 왼쪽으로 약간 밀린다.

원인은 메뉴가 **스크롤 상자 안에** 있었기 때문이다. 스크롤바가 생기면 내용 폭이 줄면서 메뉴도 함께 줄었다.
`sticky` 는 위아래만 잡아줄 뿐 폭 변화는 막지 못한다.

카드를 두 칸으로 나누고 스크롤을 아래 칸에만 줬다.

```
#tune          ← 세로 flex, overflow:hidden
 ├ .menu       ← flex:0 0 auto (스크롤 밖)
 └ .body       ← overflow-y:auto (여기만 스크롤)
```

슬라이더도 같은 이유로 흔들려서 `.body` 에 `scrollbar-gutter:stable` 을 주고,
스크롤바 폭 8px + 오른 여백 6px = 왼 여백 14px 로 좌우를 맞췄다.

## 20. 미끄러져 들어오는 패널

> p를 누르면 오른쪽에서 스르륵 나타나게 할 수는 없는가?

`display` 는 전환이 안 걸리므로 class 토글 + `transform` 으로 바꿨다.

```css
#tune   { transform:translateX(calc(100% + 20px)); opacity:0;
          visibility:hidden; pointer-events:none;
          transition:transform .22s ease, opacity .22s ease, visibility 0s .22s; }
#tune.on{ transform:none; opacity:1; visibility:visible; pointer-events:auto;
          transition:transform .22s ease, opacity .22s ease, visibility 0s; }
```

`visibility` 지연을 열 때 0, 닫을 때 .22s 로 다르게 둬야 미끄러져 나가기 전에 사라지지 않는다.

**검증이 실제 버그를 잡았다.** 화면 갱신 루프가 아직 `style.display === 'block'` 으로 열림을 판정하고 있었다.
`flex` 로 바꿨을 때부터 이미 깨져 있었고, 증상이 조용해서(휠 확대가 슬라이더에 반영 안 됨) 눈으로는 늦게 발견될 것이었다.
이후 열림 판정을 전부 class 로 통일하고, 그 사실을 검사하는 항목을 넣었다.

## 28. 침로란

> 침로는 뭐지?

뱃머리가 향한 방향. 북을 0°로 시계 방향으로 잰다.
**침로(heading)와 항적(course over ground)은 다르다** — 해류가 밀면 실제 진행 방향이 어긋난다.
화면의 `대지속력` 도 같은 짝으로, 땅에 대해 실제로 나아가는 속도다.

## 29. 대항해시대 2 화면 구조

> 2번이 오른쪽 메뉴화면, 3번이 왼쪽에 위치. 이해한 것을 설명만 하라.

지도를 가운데 두고 좌우에 세로 띠를 두는 구조로 이해했다.
오른쪽은 날짜·풍향·조류·침로·속도·일수, 왼쪽은 선박 상태와 화물이다.

**중요한 차이 하나**: 대항해시대 2는 풍향·조류·침로를 계기 셋으로 나눴고, 우리 나침반은 하나에 겹쳐 놓았다.
또한 왼쪽 띠에 넣을 값이 지금은 거의 없다는 점, 그림 자체는 저작물이라 배치 관례만 참고할 수 있다는 점을 짚었다.

## 30. 계기는 하나로, 상태는 일반 탭으로

> 오른쪽 세개의 나침판을 하나로 합치고 왼쪽에 있는 것들을 일반탭에 넣으면 어떤가?

둘 다 이유가 있다고 답했다. 풍향·해류·침로는 **서로의 각도 차이**가 중요해서 한 계기가 낫고,
내구도·컨디션은 늘 보는 값이 아니라 탭 안이 맞다.
다만 그 값들이 아직 코드에 없어서 시스템부터 정해야 한다고 덧붙였다.

## 32. 나침반 2배 확대

> 나침판 전체 크기를 지금이 2배로 그려라.

숫자만 두 배로 하면 원만 커지고 선 굵기·글자는 그대로 남는다.
그래서 안쪽을 기준 반지름 34로 그리고 배율만 거는 방식으로 다시 짰다.

```js
const COMPASS_R0 = 34;                    // 그리는 기준
const COMPASS_R  = 68;                    // 실제 크기
ctx.translate(cx, cy); ctx.scale(R/R0, R/R0);
```

`ctx.scale` 이 선 굵기와 글꼴까지 늘려 사진 확대하듯 커진다.
검증에 **배율 뒤에 `cx`/`cy` 를 다시 쓰지 않는지** 보는 항목을 넣었다(좌표가 두 번 더해지면 화면 밖으로 날아간다).

## 33. 테두리와 겹침

> 테두리와 겹치지 않게 하라.

**내가 크기를 잘못 쟀다.** 바깥 원은 `R0+8`(=42)에 배율 2가 걸려 실제 **84px** 인데, `R+8`(=76)로 계산했다.
검증 스크립트도 같은 오해를 갖고 있어 통과시켰다. 검증이 코드와 같은 착각을 하면 아무것도 못 잡는다.

숫자를 손으로 적지 않고 유도하도록 고쳤다.

```js
const COMPASS_RING = (COMPASS_R0 + 8) * (COMPASS_R / COMPASS_R0);
const FRAME_PAD = 16, COMPASS_GAP = 14;
const COMPASS_CX = COMPASS_RING + FRAME_PAD + COMPASS_GAP;
```

검증이 `frameVignette()` 를 직접 읽어 테두리 실제 폭(15.75px)을 계산해 `FRAME_PAD` 와 맞는지 확인한다.

## 36. 해류가 여전히 안 보인다

> 나침판에서 해류가 안보인다.

`_curstat.js` 를 만들어 실측 분포를 뽑았다.

| 백분위 | 유속(노트) |
|---|---|
| p10 | 0.039 |
| p50 | 0.156 |
| p75 | 0.283 |
| p90 | 0.522 |
| p99 | 1.467 |

**기준으로 쓰던 1.2노트가 거의 p99였다.** 바다의 절반이 반지름의 13%로 그려지고, 10.2%는 아예 안 그려졌다.
기준을 p90(0.52노트)으로 낮추고 제곱근을 씌워 약한 값을 끌어올렸다.

**바람의 `windFull` 때와 같은 실수를 두 번째로 한 것이다** — 데이터 분포를 안 보고 기준을 정했다.

## 37. 무조건 표시, 세기는 길이로

> 나침판에서 해류는 무조건 표시한다. 그리고 해류의 세기는 길이로 표시한다.

세기로 걸러내던 조건을 없애고 `cs > 1e-9`(정확히 0인 육지만 제외)로 바꿨다.
굵기와 색을 고정해 **세기는 길이 하나로만** 나타내게 했다. 길이 범위를 넓혀 p90/p10 차이가 2.6배가 됐다.

## 38. 방위 글자

> 나침판에 NSEW를 표시하라. 테두리에 걸치지 않게 하라.

8방위 별의 긴 가지가 정확히 N·S·E·W 방향으로 뻗어서, 글자를 안쪽에 두면 겹친다.
금색 원 바깥에 띠(`COMPASS_PAD = 18`)를 만들어 그 한가운데 넣었다. 북만 밝게 두었다.

검증이 글꼴 크기를 읽어 글자의 위·아래 끝이 두 원 사이에 들어가는지 산술로 확인한다.

## 39. 침로를 테두리 위 점으로

> 침로는 나침판 테두리를 붉은 작은 동그라미가 움직이면서 보여주는 형식으로 하자. 이해한 것을 미리보기하라.

세 가지(금색 원 위 / 점과 바늘 병행 / 바깥 띠)를 그렸다.
바깥 띠는 침로가 0·90·180·270°일 때 방위 글자를 덮는 문제가 있음을 짚었다.

## 40. 원과 삼각형, 불투명 바닥

> 내가 원한 것은 '나'이다. 그러면 원대신 삼각형이 나은가? 나침판은 불투명하게 한다. 이해한 것을 다시 미리보기하라.

**동그라미가 낫다**고 답했다. 삼각형을 언급했던 이유는 점만으로는 방향이 모호해서였는데,
바늘을 함께 두는 안이라 그 이유가 사라진다. 바늘은 방향, 점은 눈금 위의 자리로 역할이 갈린다.

바닥을 `rgba(30,44,41,.55)` 에서 불투명 `#223a36` 으로 바꿨다.

## 41. 바늘 제거, 바람·해류 표시 시안

> 동그라미로 하고 침로 바늘은 제거하라. 그리고 풍향과 해류의 방향과 세기를 어떻게 표시할 건지 여러개의 미리보기하라.

침로를 금색 원 위의 붉은 점으로 바꾸고 중심 바늘을 없앴다.
바람·해류는 방향이 겹칠 때 서로 가리는 문제를 먼저 보이고, 이를 피하는 세 안(동심 띠 / 테두리 막대 / 방향만+숫자)을 그렸다.

## 42. 시계바늘 방식 제안

> 풍향과 해류를 시계바늘처럼 표시하는 건 어떤가? 풍향은 굵게표시하고 해류는 조금 얇게 표시한다. 대신 해류를 풍향 위에 표시시킨다. 그리고 풍향과 해류의 속도는 나침판 여백에 표시힌다. 이해한 것을 미리보기 하라.

굵은 바람 위에 얇은 해류를 얹으면 **방향이 겹쳐도 둘 다 읽힌다.** 앞서 문제였던 겹침이 이 방식으로 풀린다.
숫자 자리를 세 가지로 그렸다.

## 43. 직사각형 바늘

> 직사각형 형태도 미리보기하라. 그리고 나침판 왼쪽 상하에 각각 바람과 해류 세기를 숫자로 표시하라. 미리보기하라.

**직사각형이 낫다**고 답했다. 뾰족한 형태는 끝으로 갈수록 둘 다 가늘어져 굵기 차이가 사라진다.
직사각형은 폭이 일정해 어디서나 같은 대비를 유지한다.

## 44. 붉은 해류, 외곽 표시

> 해류는 붉은색으로 표시해서 미리보기 하라. 그리고 바람과 해류는 나침판 외곽에 표시하라. 미리보기 하라.

외곽 호와 외곽 막대를 그리고, **침로 표식도 붉은색이라 헷갈린다**는 점을 세 번째 그림으로 보였다.

## 45. 이해 바로잡기

> 네가 이해를 잘못했다. 내가 원하는 방식은 지금 올린 이미지이고, 여기서 해류는 풍향보다 얇은 굵기에 붉은색이어야 한다. 그리고 해류와 바람의 세기는 나침판 테두를 밖에 상하에 위치시켜라는 거다. 네가 이해한 것을 여러개의 미리보기로 보여라.

바늘은 중심에서 뻗는 시계바늘 그대로, 숫자만 원 **바깥**으로 빼는 것으로 다시 이해했다.
자리를 세 가지(위·아래 / 왼쪽 위·아래 / 아래 한 줄)로 그렸다.
바늘이 선이고 침로가 점이라 모양·자리가 달라 붉은색 걱정이 줄어든다는 점도 덧붙였다.
