### 설계 — 값 둘, 규칙 하나

`step`(지금 보는 단) 옆에 `cap`(해도 최대)을 두고, 둘의 관계를 함수 하나가 지키게 했다.

```js
function clampStep(){
  const s = cap === 0 ? 0 : Math.min(Math.max(step, BTN_MIN), cap);
  if(s !== step){ step = s; saveStep(); }
}
```

합법 범위는 `cap` 이 0 이면 `{0}` 하나뿐이고, 1 이상이면 `1…cap` 이다.
**값을 따로 적지 않고 범위에서 끌어냈으므로** 결정하신 것이 전부 이 한 줄에서 나온다.

| 상황 | 결과 | 근거 |
|---|---|---|
| 6단에서 상한 3 | 6이 불법 → 3으로 내려온다 | 결정 1 앞 |
| 3단에서 상한 6 | 3이 이미 합법 → 그대로 | 결정 1 뒤 |
| 상한 0 | 0만 합법 → 해도 꺼짐 | 결정 2 |
| 상한 0 → 3 | 0이 불법 → 가장 가까운 1단 | 파생 |

마지막 줄이 규칙에서 저절로 나오는 파생이라 따로 물었고, 세 안(1단 / 상한 단 / 기본 2단) 중
**1단**을 택하셨다. 예외를 적지 않아도 되는 쪽이다.

되돌리기가 상한도 되돌리는지도 함께 확정받았다.

> 1. (a) 1단
> 2. 되돌리기(Ctrl+Z)가 상한도 되돌린다.

### 1) `ne_10m_land` 저장 형식

두 길의 갈림은 용량이 아니라 **부팅 순서**였다. `.bin`(875KB)은 `fetch` 로 비동기라
30여 개 검증이 기대는 동기 초기화를 통째로 다시 짜야 했고, `.js` + base64(1,166KB)는
`<script>` 태그로 동기 로딩된다. 25% 용량을 내주고 뼈대를 지킨 것이 B안이다.

`land_data.js` 현재 머리:

```
// Source: Natural Earth 1:10m land (public domain)
// Format: delta8. Per ring: int32 x0,y0 (lon*1000) then int8 dx,dy;
//         dx==-128 escapes to int16. 0.001 deg ~ 0.111 km. No simplification.
window.LANDBIN = { rings: 3892, points: 415936, scale: 1000,
                   format: "delta8", data: "NA8AAFQ+AACjAwEA…" }
```

파일 1.19MB, base64 문자열, 동기 로딩 — **B안 그대로 구현되어 있다.** 간략화 없이 전 점 수록.

### 2) `ZMAX=100` 임시 주석

```js

//   100 = 배 1척 ≈ 1.6km. 항해 게임 축척의 사실상 바깥쪽 끝
const ZMAX=100;                  // 기준 배율이자 상한
const ZDATA_LIMIT=132;           // 좌표 정밀도(0.001°)가 화면 3px 이 되는 배율

```

"임시" 흔적이 없고 확정 결정문으로 다시 쓰였다. 초기 배율도 100.
데이터가 132까지 견디는데 100에서 끊은 이유(남은 제약은 정밀도가 아니라 **점 간격**
— 중앙 선분 2.02km)까지 적혀 있다.

### 3) 정보 카드(I) 설명 두 곳

**바뀐 코드를 못 따라간 옛 사실**을 말하고 있었다. 현재는 둘 다 갱신되어 있다.

- ① `1:10m land` … 단순화 없이 **3,892고리 415,936점**, 고리마다 첫 점만 절대값 + `델타 int8`
- ④ 해안선 **선분** 415,936개를 격자(`1024×512`)로 색인 → 최근접 선분 거리 → 선체 반지름
  (`0.2km`) 안이면 바깥 법선으로 미끄러뜨림. **그리는 것과 막는 것이 같은 자료.**
  마스크는 해류·폭풍·육지 발견 등 거친 판정에만

카드의 숫자가 `land_data.js` 의 실제 값과 정확히 일치한다.

### 남은 문제 — 목록만 살아 있었다

**작업일지에는 이 셋의 완료 기록이 없다.** 직전 일지 부록 D 에 여전히 "미착수"로 적혀 있는데

목록만 지우지 못한 채 넘어온 것으로 보인다. 이번 일지에서 정리한다.

### 새 파일 — `_specsrc.js`

### 가장 중요한 발견 — 검증이 거짓말을 하고 있었다

`verify_windsail` 이 값을 베껴 두었는데 **실제와 달랐다.**

| 값 | 베껴 둔 것 | 실제 |
|---|---|---|
| `windMin` | 1.5 | **0.5** |
| `windFull` | 10 | **9** |

```
OK   최대 풍속 이상은 100%  ≥ 9 m/s
OK   중간값이 절반          4.75 m/s = 50%
OK   상수를 이 파일에 베껴 두지 않았다   원본에서 뽑아 쓴다
```

## 8. 안내줄의 L·P 가 상태를 안 보여 준다 (진단)

> (이미지 첨부) 배율고정과 조정패널이 작동은 되는데, 바람, 해류, 경위선, 나침선처럼
> 표시가 안된다. 이해한 것을 쉽고 간단하고 짧게 설명만 하라.

원본을 읽어 확인했다. 안내줄이 **두 덩어리**로 되어 있다.

| 덩어리 | 내용 | 색 |
|---|---|---|
| `<span class="dim">` (HTML 고정) | L 배율고정 · P 조정패널 · I 정보 | **늘 회색** |
| `<span id="toggles">` (JS 가 매번 다시 씀) | Space 정지 · B 바람 · K 해류 · G 경위선 · H 나침선 · C 충돌영역 | 상태 따라 금색/회색 |

아래쪽은 `TOGGLES` 표를 돌며 `show[f]` 를 보고 `on`/`off` 를 붙인다.
위쪽은 **HTML 에 글자로 박혀 있어 상태를 아예 모른다.**

L 과 P 는 실제로 켜짐/꺼짐이 있는 것들이다 — `zoomLock` 이 참/거짓이고 패널도
열림/닫힘이 있다. 표시가 안 붙어서 지금 고정 중인지, 패널이 열려 있는지
안내줄만 봐서는 알 수 없다. I(정보)는 켜짐이랄 게 없는 한 번짜리 여닫기라 성격이 다르다.

**설계 지점**: `TOGGLES` 는 지금 `show` 객체 하나만 보게 되어 있다. `zoomLock` 과
패널 열림처럼 **다른 곳에 사는 상태**를 어떻게 읽을지가 정해야 할 것이다.
(이어서 §9 에서 실제로 옮겼다)

## 9. 안내줄을 전부 토글로 · 정보 카드 부활

> L·P 를 `TOGGLES` 쪽으로 옮기고, 'i정보'는 제거하라.

§8 에서 설명만 했던 것을 실제로 옮기기로 했다. 설계 지점은 **"켜짐을 어떻게 읽는가"가
셋 다 다르다**는 것이었다.

| 키 | 상태가 사는 곳 |
|---|---|
| L | `let zoomLock` — 그냥 변수 |
| P | `#tune` 요소의 `on` 클래스 — **DOM** |
| Space | `let paused` — `updateHint` 안에 손으로 박혀 있었다 |
| B·K·G·H·C | `show` 객체 |

세 안을 냈다.

1. 셋째 칸을 **함수**로 바꾼다 — 읽는 방법의 차이를 함수 안에 가둔다
2. `zoomLock`·패널 열림을 `show` 객체에 넣는다 — 뜻이 안 맞고, 패널은 진실이 DOM 에 있어
   상태가 두 곳으로 갈린다
3. `updateHint` 안에서 키별로 분기한다 — 가장 적게 고치지만 표의 뜻이 무너진다

안 1 을 추천했다. `clampStep()`·`dot()` 과 같은 계열이다.

### 도중에 나온 버그 — 정보 카드가 아예 안 뜨고 있었다

> 'i' 키를 눌러도 아무런 반응이 없다. 이 키의 기능이 뭐지?

원본을 읽어 원인을 찾았다. **`#info` 에 `position` 이 없었다.**

```css
#info{top:0;left:0;right:0;bottom:0;display:none;…;z-index:5;}
```

`top·left·right·bottom` 과 `z-index` 는 **위치가 지정된 요소에만 듣는다.**
`<div id="info">` 는 `class="panel"` 이 없어 `position:static` 이었고, 그래서 저 다섯 줄이
전부 무시되고 있었다.

`I` 를 누르면 `display` 는 실제로 `none → flex` 로 바뀐다. **코드는 제대로 돌고 있었다.**
다만 화면을 덮는 대신 문서 흐름 끝의 평범한 블록이 되어, `position:fixed` 인 캔버스 셋에
통째로 가렸다. `html,body` 에 `overflow:hidden` 이 걸려 있어 스크롤해 내려갈 수도 없었다.

형제들과 비교하면 차이가 뚜렷했다 — `#cb`·`#cg`·`#c` 는 `fixed; inset:0`,
`#hint` 는 `.panel` 이 `fixed`, `#dial`·`#tune` 도 각자 `fixed`. **`#info` 만 없었다.**

세 갈래를 제시했고 아이삭이 **1번(고치고, 안내는 지운다)** 을 택했다.

> 1로 한다.

### 구현

```js
// 셋째 칸이 '켜졌는가'를 돌려주는 함수다. 상태가 사는 곳이 저마다 다르지만
// 차이를 함수 안에 가두면 표는 하나로 유지된다.
function tuneOpen(){
  const t = document.getElementById('tune');
  return !!t && t.classList.contains('on');
}
const TOGGLES = [
  ['L','배율고정', ()=>zoomLock],      // 변수
  ['P','조정패널', ()=>tuneOpen()],    // DOM 클래스
  ['Space','정지', ()=>paused],        // 변수
  ['B','바람',     ()=>show.wind],     // show 객체
  ['K','해류',     ()=>show.cur],
  ['G','경위선',   ()=>show.grat],
  ['H','나침선',   ()=>show.rhumb],
  ['C','충돌영역', ()=>show.coll]
];
```

**정지의 특례가 사라진 것**이 덤이었다. 옛 `updateHint` 는 Space 한 줄을 손으로 짜 넣고
나머지만 표로 돌렸다. 이제 여덟이 같은 길을 지난다.

`tuneOpen()` 은 `#tune` 의 클래스를 읽는다 — 상태를 따로 변수에 두지 않았다.
두면 진실이 두 곳으로 갈린다.

표시할 키 글자를 표에 그대로 적었다(`'L'`, `'Space'`). 옛 코드의 `k.toUpperCase()` 로는
`Space` 를 다룰 수 없어 그것이 특례의 원인이기도 했다.

함께 정리한 것:

- `<span class="dim">` 껍데기와 `#hint .dim` CSS 두 줄 제거
- `updateHint` 앞머리의 `' · '` 제거 (dim 이 없어져 줄이 점으로 시작하게 됨)
- `#info{position:fixed; …}` 한 줄 추가

### 제가 잘못 짰다가 고친 것 — 갱신 순서

처음엔 `updateHint()` 호출을 **상태를 바꾸기 전에** 두었다. 그러면 `L` 을 눌러도 색이
한 박자 늦게 바뀐다. 상태 변경을 모두 끝낸 뒤 한 번만 부르도록 옮겼다.

```js
if(k==='l'){ zoomLock=!zoomLock; … }
if(k==='p'){ … t.classList.toggle('on'); … }
if(k===' ' && !e.repeat) paused = !paused;
// 안내줄 갱신은 상태를 다 바꾼 뒤 한 번만. 앞에 두면 방금 누른 키가 한 박자 늦게 나온다.
if('ghckblp '.includes(k)) updateHint();
```

검사도 함께 넣었다 — `갱신이 상태 변경 뒤에 온다`.

### 검증 — 낡은 검사 넷이 함께 걸렸다

전부 이번 변경으로 뜻이 달라진 것들이라 함께 고쳤다.

| 파일 | 옛 검사 | 새 검사 |
|---|---|---|
| `verify_minimap` | `'ghckb'.includes(k)` 를 못박음 | 키 목록을 **뽑아서** M 이 없는지 확인 |
| `verify_ship` | `paused?'on':'off'` 를 찾음 | 표에 `['Space','정지',…]` 가 있는가 + **따로 그리지 않는가** |
| `verify_zoom` | `<kbd>P</kbd> 조정패널` | 표에 L·P 가 있는가 + 갱신 키에 `l`·`p` 가 있는가 |
| `verify_menu` | `L·P·I 안내는 남아 있다` | 안내줄이 토글 목록과 fps 뿐인가 + I 키 조작은 사는가 |

`verify_minimap` 의 M 검사는 목록 자체를 뽑아 보게 바꿨다. 못박아 두면 안내줄에 항목을
더할 때마다 깨진다.

```js
const hintKeys = (src.match(/'([a-z ]+)'\.includes\(k\)\) updateHint/) || ['',''])[1];
chk('M 키가 비었다 — 새 기능 예약석',
    !/if\(k==='m'\)/.test(src) && hintKeys.length > 0 && !hintKeys.includes('m'),
    `안내줄 갱신 키: ${hintKeys.trim()}`);
```

이번 버그를 겨냥한 파수꾼도 넣었다. **화면에 실제로 뜨는지를 아무도 안 보고 있었던 것**이
이 버그가 오래 숨어 있던 이유다.

## 부록 C. 이번에 효과가 있었던 방법

**1. 값을 적지 않고 관계에서 끌어낸 것.**
`clampStep()` 의 합법 범위 하나로 결정 사항 넷과 파생 하나가 전부 나왔다.
"0에서 풀리면 몇 단인가" 조차 규칙의 결과였고, 그래서 예외를 적지 않아도 됐다.
직전 세션의 `RING_R` 과 같은 계열 — **값을 고정하는 것보다 관계를 고정하는 편이 낫다.**

**2. 이름을 뜻과 함께 바꾼 것.**
`*dialStep` 을 `*dialCap` 으로 갈고 `!/dialStep/` 파수꾼을 세웠다. 뜻만 바꾸고 이름을
두면 다음에 읽는 사람이 속는다. 개명은 검증 여섯 자리를 함께 고치는 비용이 있었지만
한 번으로 끝난다.

**3. 문제를 만든 쪽을 정확히 짚은 것.**
간격 0 은 이번 변경이 만든 것이 아니라 이전부터 있던 것이 드러난 것이었다.
"제가 그랬습니다"로 넘어갔으면 `.tgt2` 를 되살리는 엉뚱한 수리를 했을 수 있다.

**4. 남기기로 한 쪽에도 검사를 붙인 것.**
`tgt2` 를 지우면서 `gh` 가 살아 있는지도 함께 검사했다. 제거만 지키면 나중에 둘 다
사라져도 아무도 모른다.

**5. 검사는 형태가 아니라 내용을 못박을 것.**
`snap()` 한 줄 통짜 정규식이 항목 하나 늘어난 것으로 무너졌다. 직전 세션의
`verify_helm`·`verify_ui` 와 정확히 같은 병이다. **줄 모양·인자 순서·공백에 기대는 검사는
기능이 자라는 순간 깨진다.**

**6. 목록보다 원본을 믿은 것.**
이월 항목 셋이 일지에는 미착수로 남아 있었으나 코드에는 다 들어가 있었다.
확인하지 않고 착수했으면 같은 일을 두 번 할 뻔했다.

**7. 뽑아 쓰는 일을 한 곳으로 모은 것 (`_specsrc.js`).**
세 파일이 같은 병을 앓고 있어 각자 고치는 대신 도구를 하나 만들었다.
`lift()` 가 `SHIP`·`P` 를 **둘 다** 넘기게 한 것이 핵심이다 — 한쪽만 넘기면
나머지를 베껴 두게 되고, 그것이 바로 이번 사고의 원인이었다.
표가 또 갈려도 `specTable()` 한 곳만 고치면 된다.

**8. 통과하는 검사도 의심할 것.**
`verify_windsail` 은 `windMin` 을 1.5 로 베껴 두고 **통과하고 있었다.** 실제는 0.5 다.
`verify_zoom` §2 는 `P.speedKn` 이라 부르며 `SHIPS` 쪽 글자에 얻어걸려 통과했다.
어제 얻은 교훈 — *"검사가 통과한다고 검사가 살아 있는 것은 아니다"* — 의 한 단계 위다.
**실패는 눈에 띄지만 거짓 통과는 안 띈다.** 값을 베껴 둔 검사는 전부 후보다.

**9. 검사가 '글자가 있는가'만 보면 '화면에 뜨는가'는 아무도 안 본다.**
정보 카드는 `id="info"` 도, 키 처리도, HTML 내용도 다 있어 모든 검사를 통과했다.
그런데 `position` 한 줄이 없어 **한 번도 보이지 않았다.** 존재를 세는 검사만으로는
이런 것이 안 잡힌다. 화면에 관한 것은 '어떻게 놓이는가'까지 봐야 한다.

**10. 왜 그렇게 되어 있는지 먼저 읽은 것.**
"L·P 를 옮겨라"는 한 줄짜리 지시였지만, 옮길 자리(`TOGGLES`)가 `show` 객체만 읽는
구조라는 것을 먼저 확인했다. 그래서 셋째 칸을 함수로 바꾸는 설계가 나왔고,
덤으로 정지의 특례까지 함께 사라졌다. 바로 손댔으면 분기만 늘었을 것이다.
