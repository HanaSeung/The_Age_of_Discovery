## 48. 구현 방법 추천

> 내가 원하는 건 '나'안이다. 가로크기는 패널의 가로 크기와 같게 하라. 구현방법에 대한 너의 추천은 무엇인가?

**카드는 HTML, 나침반은 그 안의 전용 캔버스**를 권했다.

- 조정 패널의 CSS 규칙을 그대로 써서 모습이 저절로 맞는다
- 화면 어디에 놓을지 계산하는 코드가 통째로 사라진다(중심 = 캔버스 한가운데)
- 숫자를 HTML로 두면 글꼴이 다른 UI와 같아지고, 값이 바뀔 때만 갱신하면 된다

비용으로는 캔버스가 하나 더 늘고, 실수로 전역 `ctx` 에 그리면 지도 위에 겹쳐 나온다는 점을 짚었다.

## 50. 검은 화면 — 선언 순서 오류

> 게임 화면이 제대로 나오지 않는다.

`const` 는 끌어올려지지 않아 선언 전에 건드리면 스크립트가 통째로 죽는다.

**기존 검증 셋은 전부 통과했다.** 정규식으로 "코드가 이렇게 쓰였나"만 보고 있어서 실행하면 죽는다는 사실을 잡을 방법이 없었다.

그래서 `verify_boot.js` 를 만들었다. Node의 `vm` 위에 작은 DOM·캔버스 대역을 깔고 페이지를 실제로 실행한다.

- 본문 스크립트가 끝까지 실행되는가 (죽으면 몇 번째 줄인지 알려준다)
- `resize()` · `compass()` · `drawShip()` 이 도는가
- 나침반이 **제 캔버스에만** 그리는가 (지도 캔버스 호출 0회)
- 조정 패널이 만들어지는가

이 스크립트에 넣고 돌리자 첫 줄에서 바로 잡혔다. `COMPASS_SIZE` 도 같은 이유로 걸려 두 번째 오류가 드러났다.

## 57. 흘수의 실제 뜻

> 흘수는 물건을 많이 싣을때 물에 잠기는 정도이다. 즉, 배의 속력에 영향을 미친다. 참고하라.

**내가 잘못 알고 있었다.** 흘수를 "지나갈 수 있는 최소 수심"으로만 다뤘다.
적재량에 따라 변하는 값이고, 잠긴 만큼 저항이 커져 속력이 준다.

따라올 변경(흘수를 계산값으로, 속력 계산에 항 추가, 항목별 무게)을 정리하고,
교역품이 생길 때 함께 다루는 편이 나을 수 있다고 덧붙였다. 지금은 표시만 한다.

> '나'형으로 하되, 텍스트 크기를 좀더 키우면 좋겠다.

```
내용폭 260 = 라벨 58 + 사이 8 + 막대 114 + 사이 8 + 값 72
```

라벨 12 → 13px, 값 13 → 15px. 12항목 기준 638 → 482px 로 24% 짧아졌다.

## 73. 디버그 탭도 같은 형식

> 디버그의 각종 데이터들도 같은 형식으로 만들어라.

기본값을 줄에서 빼고 `title` 로 넘겼다. 대신 **기본값에서 벗어난 값은 초록색**으로 표시한다 —
실제로 더 자주 궁금한 것은 "기본값이 얼마인가"가 아니라 "내가 뭘 건드렸는가"다.

## 74. 값이 잘림 — 설명만

> 세로 스크롤에 가려진다. 이해한 것을 간단하게 설명만 하라.

두 가지가 겹쳐 보였다. 값이 오른쪽에서 잘리는 것과, 긴 라벨이 두 줄로 접히는 것.
**내 검증이 일반 탭 라벨만 보고 디버그 탭의 `가속(→전속)` 을 빠뜨렸다**는 점을 인정했다.

## 75. 원인은 슬라이더의 최소 폭

> 오른쪽 텍스트를 왼쪽으로 조금더 옮기면 안되는가?

옮기는 것만으로는 다시 잘린다. **`input[type=range]` 가 `min-width:auto` 라 고유 폭(약 129px) 아래로 안 줄어들어** 값 칸을 밀어냈다.

`min-width:0` 을 주고 폭을 다시 나눴다.

```
디버그  260 = 라벨66 + 사이6 + 슬라이더104 + 사이6 + 값78
일반    260 = 라벨66 + 사이8 + 막대108  + 사이8 + 값70
```

긴 라벨을 줄였다: `가속(→전속)`→`가속`, `내구도 정원`→`내구도`, `시계 1초 =`→`시계`.
검증이 두 목록에서 라벨을 전부 뽑아 가장 긴 것을 계산해 확인하도록 고쳤다.

## 76. 글꼴 확인

> 숫자와 텍스트의 폰트가 같은가?

아니다. 라벨은 산세리프, 값은 Georgia. **게다가 항해일과 디버그 출력 상자는 monospace라 숫자 글꼴이 두 벌이었다.**
Georgia는 옛날식 숫자를 써서 3·4·5·7·9가 기준선 아래로 내려간다는 점도 짚었다.

## 77. 글꼴 시안

> 각각의 안대로 미리보기하라.

monospace / Georgia+라이닝 / 산세리프 / Georgia 통일 넷을 그렸다.

## 78. Georgia에 한글이 없다

> '라'의 한글은 숫자와 같은 폰트인가?

아니다. **Georgia에는 한글 자형이 없어** 시스템 글꼴로 대체된다.
문제는 디버그 탭의 값(`66 °/초`)처럼 **한 값 안에서** 글꼴이 갈린다는 것.

앞서 monospace를 권했던 것을 **산세리프로 바꿨다** — monospace에도 한글이 없어 같은 문제를 갖는다.

## 79. 시스템 글꼴 후보

> 최대한 숫자 폰트와 유사한 폰트를 찾아줘. 아니면 대항해시대에 어울릴만한 폰트를 미리보기해줘.

바탕 · 궁서 · 나눔명조 · 맑은 고딕 · 돋움 · 나눔고딕을 실제로 그려 비교했다.
**바탕**을 권했다 — 한글·숫자·로마자가 한 벌이고, 세리프이며, 윈도우 기본 탑재다.
다만 인쇄용이라 작은 크기에서 가늘어져 14~15px로 올려야 한다는 점을 덧붙였다.

## 80. 웹폰트 후보

> 현재 없는 글꼴중에서도 대항해시대나 현재 숫자 폰트와 가장 잘 어울리는 한글폰트는 무엇인가?

구글 폰트에서 받아와 본명조 · 함렛 · 고운바탕 · 나눔명조 · 송명을 실제로 그려 비교했다.
**본명조(Noto Serif KR)** 를 권했다 — Georgia와 성격이 가깝고, 한글·숫자가 한 벌이며, 굵기가 일곱 단계다.

치를 값도 적었다: **이것이 첫 외부 의존이 된다.** 한글 글꼴은 크지만, 쓰는 글자만 잘라내면 수십 KB로 줄일 수 있다.

## 81. 날짜 숫자 글꼴 통일

> 일단 올린 이미지의 숫자에도 동일한 숫자 폰트를 적용시켜라.

날짜·항해일 숫자를 `<b>` 로 감싸 값과 같은 글꼴로 뽑았다. 항해일의 monospace가 사라졌다.

앞으로를 위해 숫자 글꼴을 변수 하나로 모았다.

```css
:root{ --numfont: Georgia, serif; }
```

여섯 곳이 이걸 쓴다. 글꼴을 정하면 한 줄만 고치면 된다.
**나침반 캔버스 글자는 CSS 변수를 못 읽어** 따로 맞춰야 한다는 것을 주석과 검증에 남겼다.

## 82. 날짜를 라틴 문자로

> 년월일요일을 영어로 표기하고 맨앞에 A.D. 를 표기하라.

```
   A.D. 1500  Feb 18  Tue
        항해 49일차
```

뜻밖의 이득이 있었다 — 날짜 줄이 통째로 라틴 문자가 되어 **글꼴 섞임이 이 줄에서는 사라졌다.**

검증이 시작 요일을 율리우스일수로 다시 계산해 `EPOCH_DOW = 3` 과 맞는지 보고,
월 이름 개수가 달력의 월 길이 배열과 같은지 확인한다.

# 부록 C. 이번에 유효했던 작업 방식

**실행하는 검증을 따로 둔다.** 정규식 검사 셋이 전부 통과한 상태에서 화면이 새까맣게 나왔다.
`verify_boot.js` 는 페이지를 실제로 돌려 이 종류의 죽음을 첫 줄에서 잡는다.

**숫자를 손으로 적지 말고 유도한다.** 나침반 반지름을 `R+8` 로 잘못 재어 테두리를 넘었고,
검증도 같은 오해를 갖고 있어 통과시켰다. 지금은 `COMPASS_RING` 을 계산해서 쓰고 검증이 그 식을 확인한다.

**데이터 분포를 보고 기준값을 정한다.** 해류 기준을 p99로 잡아 바다의 절반이 안 보였다.
바람의 `windFull` 때와 같은 실수를 두 번째로 한 것이다. `_curstat.js` 처럼 분포부터 뽑는 습관이 필요하다.

**한 곳에서만 정하게 만든다.** 열림 판정이 두 군데로 흩어져 하나가 조용히 깨졌고,
숫자 글꼴이 세 벌로 갈려 있었다. 지금은 class 하나, `--numfont` 하나로 모았다.

**"이해한 것을 설명만 하라"가 잘 작동했다.** 구현 전에 이해를 맞추는 단계에서 여러 번 어긋남을 미리 잡았다.
